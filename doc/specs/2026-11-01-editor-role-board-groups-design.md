# 운영자 역할 + 부서·게시판 연동 — 설계

2026-11-01 사용자 승인. 구현 계획: `doc/plans/2026-11-01-editor-role-board-groups.md`

## 배경
- 역할이 관리자(`admin`)·일반 회원(`member`) 둘뿐이라, 게시판에 글만 올릴 사람에게도 관리자 권한(회원 관리·사이트 설정 등)을 줘야 했다.
- 부서 게시판(글쓰기 권한 '부서') 16개에 부서가 하나도 연결되지 않아 사실상 관리자만 글을 쓸 수 있었다. 게시판 하나에 부서 하나만, 그것도 게시판 관리(사이트 설정 관리자) 화면에서만 연결할 수 있었다.

## 결정 사항 (사용자 선택)
| 항목 | 결정 |
|---|---|
| 운영자 글쓰기 범위 | 모든 게시판 (관리자 전용 게시판 포함). 관리자 화면은 못 들어감 |
| 운영자 수정·삭제 | 자기 글만 |
| 부서 연동 방식 | 부서 관리에서 부서마다 글 쓸 게시판을 여러 개 고름 |
| 초기 연결 | 청년부 → 청년회 게시판 |

## 1. 운영자 (`profiles.role = 'editor'`)
- 회원 관리 '권한'에 일반 회원 / 운영자 / 관리자. 관리자 누구나 지정 (사이트 설정 관리자 보호 규칙은 그대로)
- DB 함수 `is_editor()`: 승인됐고 차단되지 않은 운영자
- `can_write_board`: 글쓰기 '관리자'·'부서' 게시판에 운영자 허용 ('회원' 게시판은 원래 승인 회원 누구나)
- 수정·삭제 RLS는 그대로(작성자 본인 또는 관리자) → 운영자는 자기 글만
- 상단 고정·회원 전용 지정은 그대로 관리자만 (`is_admin()`)
- 관리자 화면(`/admin`)·헤더 관리자 버튼·사용자 화면 관리 버튼은 `role = 'admin'`만 → 운영자에게 안 보임 (변경 없음)

## 2. 부서 ↔ 게시판 (`board_groups`)
- 새 표 `board_groups(board_id, group_id)` 기본키 둘 묶음, 게시판·부서 삭제 시 함께 삭제. RLS 켜고 정책 없음 → 서비스 키(관리자 API)·보안 정의 함수만 접근
- `boards.group_id`는 `board_groups`로 옮긴 뒤 삭제
- 글쓰기 '부서' 게시판: 관리자·운영자 또는 연결된 부서 중 하나에 속한 승인 회원
- 부서 관리(관리자 누구나): 부서 카드에 연결된 게시판 표시 + '게시판 연결' 창에서 글쓰기 '부서'인 게시판만 체크
- 게시판 관리(사이트 설정 관리자): 부서 선택 칸 삭제, '연결된 부서' 표시만 (변경은 부서 관리에서)
- 글쓰기 권한 이름: 관리자·운영자 / 부서 (+관리자·운영자) / 로그인 회원

## 3. 검증
- SQL: 트랜잭션 안에서 임시 운영자·부서원·일반 회원 상황을 만들어 게시판 종류별 `can_write_board` 확인 후 롤백
- 화면: 회원 관리 운영자 지정·표시, 부서 관리 게시판 연결, 게시판 관리 연결 부서 표시
- `npm run lint`·`npm test`·`npm run build`
